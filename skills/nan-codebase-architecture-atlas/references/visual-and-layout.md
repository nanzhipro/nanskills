# 视觉系统与布局规范

模板内置 OpenAI 式单色视觉系统，并以 CSS 令牌层提供四套可选主题(light/dark/paper/sepia)。本文件是它的令牌表、形态语义与布局/目检规则。**默认主题保持单色**——信息层级靠字重、灰阶与线型表达；主题是令牌覆盖、不改变形态语义，也不要引入彩色与渐变。

## §1 视觉令牌

| 令牌 | 值 | 用途 |
|---|---|---|
| 底色 | `#ffffff` / `#fafafa` | 画布 / 次级面板 |
| 墨色 | `#0d0d0d` | 正文、root/内核实体填充 |
| 次级文字 | `#6e6e6e` / `#a3a3a3` | tagline / 副标题 |
| 发丝线 | `#ececec` / `#e0e0e0` / `#c9c9c9` | 分隔线 / 边框 / 节点框 |
| 字体 | `-apple-system, "SF Pro Text", "PingFang SC"` | 全局;等宽 `ui-monospace, "SF Mono", Menlo` 用于路径/CLI |
| 圆角 | 节点 10px / 卡片 13px / 控件 7–8px | |
| 节点结构 | 三行:TYPE(9px 大写追踪)· 名称(13.5px 600)· tagline(11px 灰) | 标准 208×70,大节点 250×86 |

## §2 形态语义(图例即契约)

图例由引擎按本项目实际用到的 kinds/relKinds 自动生成,其含义锚定在 11 种形态原语上:

- **黑底白字(form=black)= 最高权限**:内核接口、特权实体。整个图里黑色只能给它们。
- **白底加粗框(bold)= 服务端**;**白底常规框(plain)= 普通进程内实体**。
- **虚线框(dashed / dashedgray)= 被链接的库与被托管的工作者**(无独立控制面)。
- **浅灰底(gray / ext)= 扩展类与外部实体**;**灰框(store)= 存储**;**极浅灰底(artifact)= 构建产物**。
- **等宽字体名(mono)= CLI/工具**;**ROOT 徽章 = 非 black 但以 root 运行的实体**(实体带 `root: true`)。
- 边:实线=同步调用,虚线=网络,点线=广播/交互,细灰=构建期;加粗=特权通道。悬停任何边会变黑加粗,单击看关系详情。

kind → form 的映射是项目数据(见 `references/ontology-modeling.md` §2):哪个语义种类
配哪种形态由建模者决定,但形态本身的视觉语义(尤其 black 的稀缺性)是全图契约,不要乱配。

## §3 布局规则与目检清单

### 排布规则

1. **先组框后节点**:组框表达部署边界(一台终端/一个进程/一条供应链),组框之间留 ≥60px 通道供走线。
2. **流水线单方向**:数据平面左→右或上→下,一条视图只选一个主轴;控制平面(配置/上报)放底部横排。
3. **节点间距**:中心距 ≥260px(横向)/ ≥130px(纵向);标签碰撞先挪节点,不要缩字号。
4. **长对角线 = 重排信号**:边跨越两个以上组框,说明有一端站错了位置——把它挪到对端旁边。
5. **底行对齐**:同一排的节点 y 坐标取相同值;同类节点 x 对齐成列。
6. **视图规模**:每视图 ≤22 节点;超出就拆成两个 L3 视图,用 `drill` 串联。
7. **避开图例死区**:fit 全图截图时,左下角图例面板会覆盖画布近似 `x < 0.25×canvasW 且 y > 0.60×canvasH` 的区域(默认窗口 1680×1050 实测)——排布时别让节点落入;截局部细节图可改用 `NOLEGEND=1` 收起图例。lint 脚本会对落入死区的节点报警。
8. **协议/接口列扇形(已知好用模式)**:画「谁实现、谁调用」的协议拓扑时,把协议节点排成中间一列(或两列),实现方与调用方分居两侧;「实现」边按同一高度水平对齐(零穿越),「调用」边按目标协议的高度排序发出,顺序不对就会擦过相邻协议盒的边角。两侧节点与协议列的垂直间距 ≥130px,给扇形留出发散空间。
9. **边密度过高先剪枝,不要硬排**:同一对节点间存在双向 XPC/通知等次要边时,用该视图的 `edgeHide` 隐藏冗余方向(被隐藏的边在其它视图仍可见);L1 全景尤其如此。硬排每一条边只会让走廊互相挤压。
10. **向已收敛视图加节点:先查走廊,再查邻居,两难就换视图**。跑 lint 看「边穿节点」WARN——两簇之间的对角走廊(跨簇调用边,如 tools→permissions、guard→tools 一类)很容易被新节点拦腰穿过,换位置时这类边还会反复拦截;同时新节点若与所在视图内实体无边,lint 会报「孤立无边」。正解是优先放在有同视图边的语义邻居旁,并把那几条穿节点边依次纳入检查;几何与语义不可兼得时,把节点挪到另一个有它关系的视图(前提是不孤立),比留在错误位置硬挤强。

### 截图目检清单(逐张过,发现即修)

- [ ] 节点两两不重叠(含 ROOT 徽章与"下钻 →"角标)
- [ ] 无孤立节点——每个节点至少一条边(除非刻意,如"外部世界")
- [ ] 边标签不压节点主体;**边标签互不重叠**——引擎把标签画在边曲线中点,两条中点相近的边(共享中点的平行边最典型)标签会完全互叠,错开节点位置即可
- [ ] 组框标签不被节点遮挡
- [ ] 组框确实包含语义属于它的节点(检查节点 ±半宽是否越界)
- [ ] 黑底节点上的文字是白的;灰底节点上的文字可读
- [ ] 长名称截断处不影响辨识度(全名在详情抽屉可见即可)
- [ ] 左下角节点未被图例面板遮挡(见排布规则 7)

### 已知渲染坑(模板已修,改代码时别再踩)

1. **SVG 默认 fill 是黑色**:任何新建图形必须显式 `fill`,不要指望"默认是白的"。
2. **黑底节点文字必须显式 `fill:#fff`**,副文字 `rgba(255,255,255,.55–.72)`。
3. **CSS 类选择器有作用域**(`.node .node-box`),在新容器(如泳道)里复用样式时,要么套同名类结构,要么内联样式补齐。
4. **虚线框用 `stroke-dasharray`,不是 `border-style`**(SVG 无 border)。
5. **拖动画布 = 触发文本选中**:pan 的 `mousedown` 若不 `preventDefault()`,浏览器会把拖动手势当成框选,被扫过的 SVG `<text>` 命中 `::selection`(黑底白字)变成黑块;同时每个 mousemove 都要额外重绘选区造成卡顿。模板已在 pan 入口 `preventDefault()` + 清选区 + `user-select:none`,并给 `#viewport` 加 `will-change: transform`、拖动中(`.panning`)禁用节点 `drop-shadow`。改 pan/zoom 代码时不要丢掉这些防线。
6. **常驻 `filter: drop-shadow` 的 SVG 元素是逐帧光栅单元**:几十个节点一起平移时每个都要重光栅,是拖动卡顿的主因;阴影效果应限制在 hover/selected 或拖动中禁用。

## §4 边几何速查(手算布局时逐条对照,lint 与引擎共用此模型)

排布前先看这里,别用直觉几何——节点比想象大,边不是直线。

- **节点尺寸**:普通 **208×70**,`big:true` 的 **250×86**(半宽 104/125,半高 35/43)。中心距规则(§3-3)即由此而来。
- **方向判定**:`|dx| ≥ |dy|` 走水平边(H),否则垂直边(V);`dir` = 目标在源的方向(±1)。
- **H 边锚点**:`x1 = sx + dir·sw/2, y1 = sy`;`x2 = tx − dir·tw/2, y2 = ty`。**y 取节点中心**,不是上下边缘。
- **V 边锚点**:`x1 = sx, y1 = sy + dir·sh/2`;`x2 = tx, y2 = ty − dir·th/2`。**x 取节点中心**。
- **弯度**:`bend = min(max(|d|×0.42, 36), 150)`,d 为主轴位移;H 边 c1/c2 只在 x 方向偏移 ±bend,V 边只在 y 方向。
- **平行偏移(byPair)**:同一对 (s,t) 的第 k 条边 `off = (k − (n−1)/2)×17`;存在反向边 (t,s) 时再叠加 ±11(字典序 s<t 取 +11)。法线方向按 (s<t ? 1 : −1) 翻转,**控制点偏移要 ×1.6**,端点 ×1。
- **标签中点** = 曲线 **t=0.5** 处 = `(x1+3c1+3c2+x2)/8`,不是两端点均值——共享中点的平行边标签必互叠。
- **穿节点判定**:lint 按 t∈[0,1] 采样整条曲线,擦到节点盒边缘即报;手算要留 ≥10px 净空,别贴边。
- **lint 实测参数(2026-08 验证)**:穿节点判定 = 贝塞尔 B(t) 在 t∈[0.1,0.9] 步进 0.04 逐点采样,落在目标节点盒**内缩 8px** 的矩形内即告警(内缩不是外扩,手算常过度保守);边标签互叠阈值 = 两标签中点(曲线 t=0.5 处)欧氏距离 < 18px;节点重叠判定 = 盒距 < -2px。手调坐标时可直接按此模型精算,不必盲试。

## §5 无视觉环境的目检替代(纯文本模型专用)

§3 的截图目检依赖看图。模型无视觉能力时,按此顺序做等价验证,并在交付说明里声明「未经人眼目检」:

1. **DOM 渲染验证**:`chrome --headless --dump-dom "<入口URL>#/view/<id>"`,检查 ① 每个视图名与关键实体名出现 ② `<text>` 元素数 ③ 不是 neterror/404 模板(错误页特征是 ~187KB 的 `ERR_` 模板或 ~457B 的 404 页,标题不含图名)。引擎预渲染全部视图到单一 SVG,所以各视图 DOM 大小相同是正常的,验证时拿一份 dump 全量 grep 即可。dump 输出可能整行无换行——`grep -c` 数的是"行"不是"次数",计数用 `grep -o ... | wc -l`。
2. **PNG 墨迹覆盖率**:stdlib zlib 解 PNG 统计非白像素占比。内容图通常 2–9%(实测密集视图 6.3–8.3% 属正常);空白页/错误页 <1%;>10% 疑似重影/污染,需复查。阈值只做异常筛查,不替代 DOM 验证。
3. **截图的服务器前提**:截图与 dump 前先 `curl` 确认 URL 可达、`lsof -iTCP:<port> -sTCP:LISTEN` 确认 server 存活,再怀疑 Chrome/IPv6/代理——顺序反了会白绕几轮(见 shoot_atlas.sh 头注释的 proxy 坑)。
4. 有视觉能力的场合(用户本人/视觉模型),仍以 §3 清单做最终人眼确认。
5. **dump-dom 必须给 JS 执行时间**:`--dump-dom` 不带 `--virtual-time-budget=12000` 时引擎不渲染,返回几百字节空壳(670B 实测)——误判"渲染失败"前先确认带了 budget。
6. **手动起 server 的 URL 形态**:`python3 -m http.server <port>` 根目录即当前目录,URL 是 `/Atlas.html`;shoot 脚本的 URL 是 `/<dir名>/<entry>`。404 时先 curl 确认实际可达路径再重截。
7. **墨迹统计用 PIL**:自写 zlib/struct 解 PNG 易踩坑(实测失败),`python3 -c "import PIL"` 缺则 `pip3 install pillow`。
8. **data.js 精确探针**:`cp data.js /tmp/probe.js && echo "module.exports = ATLAS;" >> /tmp/probe.js`,node require 后按 §4 公式手算几何;不要用正则剥注释后 eval——字符串里的 `sessions/*.jsonl` 一类会被 `/*…*/` 误伤。

## §6 主题系统

四套主题由 `Atlas.html` 里的 `[data-theme="…"]` 令牌块定义，`app.js` 把当前主题写到 `<html data-theme>`。引擎内不再有硬编码颜色——节点/边/组框/时序/图例的颜色全部收敛为 `var(--token)`，主题只需重映射令牌值。

- **主题**:light(默认，OpenAI 单色浅色)、dark(暗色)、paper(纸面/打印，零阴影高对比)、sepia(暖黄)。
- **默认主题优先级**:URL `?theme=<name>` > localStorage(`atlas-theme`)> `meta.theme` > light。生成时用 `meta.theme` 定默认，查看者在顶栏切换会写入 localStorage。
- **形态语义保真**:11 种 form 的语义(尤其 black=最高权限)是全图契约，不随主题变。dark 下 black 反转为最亮(`--f-black-fill:#f2f2f2`)，仍是视觉上最突出的实体；灰底/虚线/等宽等区别按语义逐项重映射，不能图省事把黑底节点也涂黑。
- **边标签 halo 随主题换底**:`.edge text` 的描边(`--edge-label-halo`)浅色下是白、dark 下必须是 `#0d0d0d`，否则标签会带一圈白晕。时序图 `--seq-label-halo` 同理。
- **逐主题截图**:`THEME=dark bash shoot_atlas.sh <dir> 4311 overview,endpoint` 产 `<view>-dark.png`。默认主题(light)的令牌值 = 旧硬编码值，改完先截一张 light 与改前对比确认像素一致，再进新主题。
- **新增主题**只加一个 `[data-theme="…"]` 块 + 顶栏 `<option>`，不改引擎、不改 form 词表、不改校验器。
